---
description: "关闭 Gitee 上的一条 issue（按编号：先评论说明完成情况与对应 commit，再关闭）"
allowed-tools: Bash
---

从用户随命令给出的文字里拿**编号**（也可以是从上一条 `/gitee-issue-list` 结果里指的那条）。

- 用户只给了标题、没给编号：先用 Bash 跑 `gitee issue list -s open --no-tui -l 100 -j=number,title,state` 找匹配的编号。
  **标题匹配到多条或匹配不上就别猜**——列出来让用户挑一条，再往下走。
- 编号拿到后，**先把要关的那条（编号 + 标题）和下面那段评论正文一起给用户确认一次**；用户明确说「直接关 / 不用确认」才跳过。

## 1. 拟好评论正文

先在本地找这次修复对应的 commit：

```bash
git log --oneline -20
git log --oneline --grep="#<number>"   # 编号出现在提交信息里时按编号捞
```

用一两句话把**完成情况**写清楚（改了什么、验证结果如何），有对应 commit 就附上**短 hash + 标题**；
确实找不到关联 commit（改动没单独提交、只是文档 / 配置改动等）就**跳过 commit 那部分**，别硬编一个。

## 2. 先评论

用 Bash 工具跑（**不传 `-R`**，仓库跟着当前目录的 git remote 推断；**必须用 `-b` 传正文**，不给 `-b` 会弹交互编辑器，非交互环境会卡住）：

```bash
gitee issue comment <number> -b "<评论正文>"
```

**评论失败就停下**，原样贴出错误——绝不跳过评论直接关 issue。

## 3. 再关闭

```bash
gitee issue close <number>
```

然后：

- 成功后报告关了哪一条（编号 + 标题），一并带上评论正文与 `-j` 输出。
- 命令失败（没装 / 没登录 / 缺 scope / 不在 git 仓库 / 网络）**原样贴出错误**，不要自己编内容，也不要退回网页操作。
  评论已发出但关闭失败时，**重点说明 issue 目前仍是 open**，别让用户误以为已经关了。
- 只做「评论 + 关闭」：不改标题、不删 issue。
